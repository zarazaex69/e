==================================
LZMA Compressed Modules Discovery
==================================

Confirmed that CODE partition contains multiple LZMA-compressed blocks.
This indicates a modular firmware structure.

LZMA Signatures ('5d 00 00') found at:
--------------------------------------
- 0x00076428 (hit.bytes.0)
- 0x0008a2e0 (hit.bytes.1)
- 0x000a1818 (hit.bytes.2)
- 0x000ae4d8 (hit.bytes.3)
- 0x000c9800 (hit.bytes.4)
- 0x000cc22c (hit.bytes.5)

Hypothesis:
-----------
The initial entry point at 0x720A0 belongs to a bootloader or a kernel module.
Its primary task is to find and decompress these subsequent modules into RAM.

Next Steps:
-----------
1.  **Extract the first LZMA block.** Start with the one at 0x00076428.
2.  **Decompress it.** Use a standard LZMA tool or write a script.
3.  **Analyze the decompressed binary.** This will be a raw, clean ARC module.
=========================
LZMA Decompression Issues
=========================

Standard `unlzma` utility failed with "File format not recognized".

Hypothesis:
-----------
Intel uses a custom LZMA implementation. The stream is likely raw, without the standard 13-byte header.
All metadata (sizes, properties) is probably stored externally in the $MAN module manifest.

Next step: Reverse engineer the $MAN manifest structure to find the required decompression parameters.
======================================
SUCCESS: Custom Unpacker 'm1u' Built
======================================

Developed a custom C tool 'm1u' to parse the firmware and handle the proprietary Intel LZMA format.
The tool successfully bypasses the invalid LZMA header by reconstructing it with the correct uncompressed size from the $MOD entry.

First module 'KernelPriv' has been successfully decompressed.

- Compressed Size:   81,512 bytes
- Decompressed Size: 240,900 bytes
- Output File:       reverse/me1/unpacked_modules/KernelPriv.bin

The path is clear for batch decompression of all remaining modules.
