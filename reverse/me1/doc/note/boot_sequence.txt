Intel ME 1.x - Boot Sequence & Module Loading Chronology


Purpose: Establish module loading sequence for structured reverse engineering approach.

BOOT ARCHITECTURE
==

Firmware Structure:
- Flash Partition Table ($FPT) at 0x10
- CODE partition at 0x72000 (size: 0x70000)
- Entry point: 0x720A0 (offset +0xA0 from CODE base)
- 18 modules total: 7 LZMA compressed, 11 uncompressed

BOOT PHASES
==

Phase 0: Hardware Reset & ROM

Status: Not accessible for analysis (on-chip ROM)

Actions:
- ARC processor starts from ROM
- ROM initializes basic hardware
- ROM transfers control to CODE partition entry point (0x720A0)

Phase 1: Initial Bootloader (Entry Point)

Address: 0x720A0
Module: Embedded in CODE partition (not a separate module)

Actions:
- Parse $MAN manifest (module metadata)
- Initialize LZMA decompressor
- Prepare memory for module loading
- Transfer control to PRELOADER

Evidence:
- "Large dispatcher or part of bootloader" (code_entry_point.txt)
- "Complex, indirect branching" - typical for bootloader

Phase 2: PRELOADER
-
Module: PRELOADER (4,288 bytes, uncompressed)
Type: 0x07 - Kernel Preloader
Priority: HIGH (loaded first)

Actions:
- Load and decompress KernelPriv
- Load and decompress KernelNonPriv
- Setup privileged/non-privileged separation
- Initialize basic kernel structures
- Transfer control to KernelPriv

Evidence:
- Name "Preloader" clearly indicates role
- Type 0x07 - special type for kernel loader
- Small size (4KB) - only loading code

Phase 3: Kernel Initialization
-
Modules: KernelPriv (240KB) + KernelNonPriv (250KB)
Type: 0x2B (Privileged) + 0x21 (Non-privileged)
Priority: CRITICAL

KernelPriv actions:
- Initialize privileged mode
- Setup MMU/MPU (if present)
- Initialize interrupts
- Create system tables
- Start task scheduler

KernelNonPriv actions:
- Initialize user space
- Load system services
- Prepare API for modules

Evidence:
- 3,567 'bl' instructions in KernelPriv - thousands of functions
- Largest modules after UPEK
- Strings "KernelPriv" & "KernelNonPriv" in string_analysis.txt

Phase 4: BRINGUP - Early Hardware Init
-
Module: BRINGUP (8,148 bytes, uncompressed)
Type: 0x05 - Bring-up module
Priority: EARLY (after kernel)

Actions:
- Initialize critical hardware
- Setup buses (PCH, LPC, etc.)
- Initialize timers
- Basic power configuration
- Prepare for overlay module loading

Evidence:
- Type 0x05 - special type for bringup
- Name clearly indicates early initialization
- Relatively small size (8KB)

Phase 5: Power Management

Modules: PMHWSEQ (12,860 bytes) + MOFFM0_OVL (6,532 bytes)
Priority: HIGH (needed for stability)

PMHWSEQ actions:
- Power Management Hardware Sequencer
- Manage power states
- Sequence power on/off operations

MOFFM0_OVL actions:
- ME-OFF M0 Overlay
- Handle ME-OFF mode (ME disable)
- Overlay for special power modes

Evidence:
- Names clearly indicate power management
- LZMA compression of PMHWSEQ - important code
- "MOFFM0_OVL", "MOFFM1_OVL" in string_analysis.txt

Phase 6: BUP Overlays

Modules: BUCLS_OVL (2,664 bytes) + BUPMSEQ_OVL (10,012 bytes)
Priority: MEDIUM

BUCLS_OVL actions:
- BUP CLS Overlay
- Capability Licensing Service for boot-up

BUPMSEQ_OVL actions:
- BUP Sequencer Overlay
- Sequence boot-up operations

Phase 7: File System
-
Modules: EFFS_IOVL (8,408 bytes) + EFFS_OPOVL (12,056 bytes)
Priority: MEDIUM (needed for NVRAM access)

EFFS_IOVL actions:
- Embedded Flash File System I/O
- Low-level flash access

EFFS_OPOVL actions:
- EFFS Operations
- High-level file system operations
- Access to NVRAM partitions (NVKR, NVAL, NVTP)

Evidence:
- EFFS partition in FPT (0x50)
- Overlay architecture - loaded on demand

Phase 8: Security & TPM

Modules: TPM (265KB) + PKTPM (7,600 bytes) + PKTPMINIT_OVL (2,124 bytes)
Priority: HIGH (for secure boot)

TPM actions:
- Full TPM 1.2 implementation
- Cryptographic operations
- Boot measurements
- Key generation/storage

PKTPM actions:
- Public Key TPM
- Public key operations

PKTPMINIT_OVL actions:
- PK-TPM initialization
- Smallest module (2.1KB)

Evidence:
- TPM - second largest module (265KB)
- "KEY14" through "KEY31" in string_analysis.txt
- "SHA" algorithms found

Phase 9: Services & Support

Modules: CLS (23KB) + ALIASCHECK_OVL (4,788 bytes) + SUPPORT_OVL (9,508 bytes)
Priority: MEDIUM

CLS actions:
- Capability Licensing Service
- License/capability checking
- Feature management

ALIASCHECK_OVL actions:
- Alias checking
- Configuration validation

SUPPORT_OVL actions:
- Support functions
- Common utilities for other modules

Phase 10: Advanced Features (Optional)
-
Modules: TDT (25KB) + UPEK (373KB)
Priority: LOW (optional features)

TDT actions:
- Theft Deterrent Technology
- Anti-Theft functionality
- Remote management

UPEK actions:
- Fingerprint reader support (UPEK/AuthenTec)
- Largest module (373KB)
- Fingerprint recognition algorithms
- Biometric authentication

Evidence:
- UPEK - largest module (373KB)
- TDT - known Intel technology
- Both LZMA compressed - loaded on demand

MODULE LOADING MECHANISM


Overlay System:
- Modules with "_OVL" suffix - overlay modules
- Loaded dynamically on demand
- Save RAM (not all in memory simultaneously)
- "Module Offset" system ("MOFFM0_OVL", "MOFFM1_OVL")

Compression Strategy:
- Critical modules (kernel, TPM) - compressed to save flash
- Small modules (overlays) - uncompressed for fast access
- Large optional (UPEK) - compressed, loaded rarely

MODULE DEPENDENCIES
=

Critical path (mandatory sequence):
1. ROM → Entry Point (0x720A0)
2. Entry Point → PRELOADER
3. PRELOADER → KernelPriv + KernelNonPriv
4. Kernel → BRINGUP
5. BRINGUP → PMHWSEQ + Power overlays
6. Power → EFFS (file system)
7. EFFS → TPM (secure storage)

Parallel loading (after kernel):
- BUP overlays (BUCLS_OVL, BUPMSEQ_OVL)
- Support modules (SUPPORT_OVL, ALIASCHECK_OVL)
- Services (CLS)

Deferred loading (on-demand):
- TDT (only if Anti-Theft enabled)
- UPEK (only if fingerprint reader present)

REVERSE ENGINEERING PLAN


Priority 1 - Critical boot path:
1. Entry Point (0x720A0) - understand loading mechanism
2. PRELOADER - how kernel is loaded
3. KernelPriv - kernel architecture, scheduler
4. BRINGUP - hardware initialization

Priority 2 - System services:
5. PMHWSEQ - power management
6. EFFS_IOVL + EFFS_OPOVL - file system
7. TPM - cryptography and secure boot

Priority 3 - Additional modules:
8. CLS - licensing
9. TDT - anti-theft
10. UPEK - biometrics

Priority 4 - Overlay system:
11. All _OVL modules - understand overlay mechanism
12. Links between base modules and overlays

CONCLUSIONS
==

ME1 boot sequence:
ROM → Entry(0x720A0) → PRELOADER → Kernel(Priv+NonPriv) → BRINGUP → 
→ Power(PMHWSEQ+MOFFM0) → BUP overlays → EFFS → TPM → Services(CLS) → 
→ Optional(TDT, UPEK)

Key findings:
- Modular RTOS with privilege separation
- Overlay system for RAM conservation
- Secure boot via TPM
- Dynamic loading of optional features

This document provides structured plan for detailed reverse engineering instead of chaotic analysis.
