Rizin ARC Function Analysis Fix


Problem
-
Rizin's automatic analysis (aa/aaa) fails to properly identify functions in ARC binaries.
The entire binary gets identified as a single large function, making analysis impossible.

Root Cause

ARC architecture uses non-standard function prologues that Rizin's heuristics don't recognize.
Specifically, ME1 modules use a pattern of:
  sub sp, sp, 4
  mov r12, <size>
  b.d <target>
  sub sp, sp, r12

This pattern (hex: 047e8e53) appears at the start of many functions but isn't detected by default.

Solution

Manual function definition using Rizin's afu (analyze function until) command.

Step-by-step process:

1. Find function prologue pattern:
   /x 047e8e53

   This searches for "sub sp, sp, 4" instruction which marks function starts.

2. Define functions manually using afu:
   s 0xb8; afu 0xcc
   s 0xcc; afu 0xe0
   s 0xe0; afu 0xf4
   ...

   Where:
   - s <addr>: seek to function start
   - afu <end>: analyze function until <end> address

3. Verify functions:
   afl

   Lists all defined functions.

Alternative: Automated Approach

Use Rizin's iterator to define all functions at once:

[0x00000000]> af @@/x 047e8e53

This runs 'af' (analyze function) at every location matching the hex pattern.
However, this only creates function at first match. Manual afu approach is more reliable.

Failed Attempts
-
1. e analysis.prelude=047e8e53
   - Tried to set function prelude pattern
   - Syntax error: spaces not allowed in config values

2. af @@f:hit.bytes.*
   - Tried to iterate over search hits
   - Command syntax error

3. Automatic analysis (aa/aaa)
   - Identifies entire binary as single function
   - Useless for detailed analysis

Automation Script
-
For automation, extract addresses from /x search and generate afu commands:

#!/bin/bash
rizin -q -a arc -b 32 -c '/x 047e8e53' ALIASCHECK_OVL.bin | \
  grep -oP '0x[0-9a-f]+' | \
  awk 'NR>1 {print "s " prev "; afu " $1} {prev=$1}' | \
  rizin -a arc -b 32 -i - ALIASCHECK_OVL.bin

Impact

This fix enables proper function-level analysis of ME1 ARC modules.
Without it, reverse engineering is nearly impossible due to lack of function boundaries.

Applies to all ME1 modules using this prologue pattern:
- ALIASCHECK_OVL
- BRINGUP
- PRELOADER
- KernelPriv (partially)
- KernelNonPriv (partially)
- Most overlay modules

Notes
-
- Pattern 047e8e53 = "sub sp, sp, 4" in ARC bytecode
- Not all functions use this pattern (some use different prologues)
- Manual verification still required for complex functions
- After defining functions, run 'aaaa' for cross-reference analysis
